# Report Type: `project_construction`

Use this file when the deck is primarily a project initiation, construction planning, feasibility, investment review, or approval-oriented construction scheme deck.

## Suitable Scenarios

- project initiation report
- construction scheme report
- feasibility presentation
- investment review
- approval / decision meeting material
- construction plan review

## Default Chapter Framework

Use this framework unless the user provides a stronger one:

1. 项目背景与建设必要性
2. 建设目标与建设范围
3. 总体思路与建设方案
4. 实施路径与进度安排
5. 投资估算与资金安排
6. 项目组织与管理机制
7. 预期成效与风险保障
8. 决策事项

## What Each Chapter Must Answer

### 1. 项目背景与建设必要性

- why the project must be built
- what business, policy, management, or capability gap is driving it
- what happens if the project is delayed or not launched

### 2. 建设目标与建设范围

- what the project aims to achieve
- what is included in scope
- what is outside current scope

### 3. 总体思路与建设方案

- what the overall solution logic is
- how business, technology, process, and governance are organized
- why this scheme is reasonable

### 4. 实施路径与进度安排

- how the project will be phased
- what each phase will deliver
- whether the milestone rhythm is executable

### 5. 投资估算与资金安排

- how much investment is required
- what the cost components are
- how funding is arranged and sourced

### 6. 项目组织与管理机制

- who owns the work
- how responsibilities are split
- how execution, coordination, and governance will be closed-loop

### 7. 预期成效与风险保障

- what benefits are expected
- what key risks exist
- what safeguards reduce those risks

### 8. 决策事项

- what decision is required from leadership
- what scope, investment, mechanism, or path needs approval

## Extraction Priorities

Prioritize extracting:

- background issues
- external and internal drivers
- necessity statements
- objectives
- quantitative targets
- scope and scope boundaries
- construction principles
- overall architecture / overall scheme
- phased implementation path
- milestones
- investment amount
- cost categories
- funding source
- organizational responsibilities
- governance mechanism
- risks
- safeguards
- decision items

## Recommended Page Patterns

For background and necessity:

- `Metrics Cluster + Support Modules`
- `Research Evidence Mosaic`

For objectives and scope:

- `Comparison Table + Verdict Sidebars`
- scope cards with clear in-scope / out-of-scope boundaries

For overall scheme:

- `Architecture Evolution Row + Explanation Blocks`
- architecture / module overview with explanation blocks

For implementation path:

- timeline / roadmap page
- phase path + key deliverable page

For investment and funding:

- table + verdict sidebar
- funding composition + judgment strip

For organization and governance:

- governance diagram + role cards

For expected benefits and risks:

- benefit metrics + risk safeguard dual-zone page

For decision items:

- `Summary Cards + Recommendations Grid`
- decision list + recommendation box

## Page-Level Judgment Language

Construction pages should emphasize:

- necessity judgment
- scheme rationality judgment
- investment feasibility judgment
- governance readiness judgment
- clarity of decision request

The page should not only describe the plan. It should signal why the selected construction path is the right one.

## Weak Expressions To Avoid

Do not reduce the deck to:

- listing construction content without explaining necessity
- drawing architecture without showing implementation logic
- listing budget numbers without composition or basis
- a decision page that says only "please review" with no explicit decision point
