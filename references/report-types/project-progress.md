# Report Type: `project_progress`

Use this file when the deck is primarily a status update, milestone review, execution progress report, risk coordination report, or next-stage work planning deck.

## Suitable Scenarios

- weekly / monthly / quarterly project report
- leadership progress briefing
- phased execution review
- milestone review
- risk coordination meeting material

## Default Chapter Framework

Use this framework unless the user provides a stronger one:

1. 项目目标与总体判断
2. 立项与资源到位进展
3. 项目整体进展与里程碑达成情况
4. 重点工作/专题进展
5. 阶段成效与运行效果
6. 问题风险与影响评估
7. 应对举措与需协调事项
8. 下阶段工作计划

## What Each Chapter Must Answer

### 1. 项目目标与总体判断

- what the project is trying to achieve
- whether the current status is ahead, normal, delayed, or at risk

### 2. 立项与资源到位进展

- where initiation procedures stand
- whether budget, people, contracts, vendors, and other resources are in place

### 3. 项目整体进展与里程碑达成情况

- how far the project has progressed
- which milestones are complete, delayed, or at risk

### 4. 重点工作/专题进展

- how key workstreams are progressing
- which special topics are advancing well and which are blocked

### 5. 阶段成效与运行效果

- what stage results have been achieved
- what measurable effect, usage, or operational feedback exists so far

### 6. 问题风险与影响评估

- what the main issues and risks are
- how they affect schedule, cost, quality, scope, or target achievement

### 7. 应对举措与需协调事项

- what has already been done in response
- what support or cross-team coordination is still required

### 8. 下阶段工作计划

- what needs to be completed next
- what time, ownership, and dependencies define the next stage

## Extraction Priorities

Prioritize extracting:

- project objective
- overall status judgment
- completion rate
- milestone status
- resource readiness
- staffing / budget / procurement / contract status
- key workstream progress
- achieved results
- operational indicators
- issue list
- risk impacts
- mitigation actions
- coordination asks
- next-stage tasks
- timeline
- owner / responsibility

## Recommended Page Patterns

For overall status:

- `Metrics Cluster + Support Modules`

For resource readiness:

- readiness checklist or table + status strip

For overall progress and milestones:

- timeline / milestone status page

For key workstreams:

- multi-card workstream progress page
- progress status + issue-point combination page

For phase results:

- metrics cards + support evidence page

For issues and risks:

- risk matrix + impact sidebar
- issue list + severity markers

For actions and coordination asks:

- action cards + coordination request page

For next-stage plan:

- roadmap / gantt-like task arrangement page

## Page-Level Judgment Language

Progress pages should emphasize:

- current status judgment
- milestone achievement judgment
- deviation and risk judgment
- coordination urgency judgment
- clarity of next-step action

The page should not only list what was done. It should signal how far the project has really moved, what is blocking it, and what happens next.

## Weak Expressions To Avoid

Do not reduce the deck to:

- completed-item lists with no unfinished work or risk visibility
- milestone names without status judgment
- problem lists without impact and action
- next-step plans with no timing or ownership
