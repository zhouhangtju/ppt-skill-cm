# Report Type: `technical_research`

Use this file when the deck is primarily a technical research, capability analysis, competitive analysis, architecture understanding, trend analysis, or technology landing judgment deck.

## Suitable Scenarios

- technical research
- model analysis
- architecture / principle explanation
- capability analysis
- competitive analysis
- industry application analysis
- technical trend and landing judgment

## Default Chapter Framework

Use this framework unless the user provides a stronger one:

1. 概述与简介
2. 背景与发展
3. 原理与架构
4. 能力特点分析
5. 竞争力分析
6. 应用与落地
7. 总结与建议

## What Each Chapter Must Answer

### 1. 概述与简介

- what the subject is
- why it matters now
- what the audience should know first

### 2. 背景与发展

- what industry or technical context drove the current topic
- what trend or pressure explains its rise

### 3. 原理与架构

- how the mechanism works
- what the core architecture or technical path is

### 4. 能力特点分析

- what the subject is good at
- what its strengths and limitations are

### 5. 竞争力分析

- how it compares with alternatives
- where it is stronger, weaker, or differentiated

### 6. 应用与落地

- where it can be used
- how technical capability translates into customer or business value
- what landing path, barrier, or maturity judgment is appropriate

### 7. 总结与建议

- what the overall judgment is
- what to track, adopt, avoid, or prioritize next

## Extraction Priorities

Prioritize extracting:

- technical concepts
- principles and mechanisms
- architecture and evolution path
- capability characteristics
- quantitative indicators
- competitor comparison points
- application cases
- landing constraints
- commercialization / value-realization clues

## Recommended Page Patterns

- `Research Evidence Mosaic`
- `Comparison Table + Verdict Sidebars`
- `Architecture Evolution Row + Explanation Blocks`
- `Observation Bar + Case Grid + Judgment Strip`
- `Value Chain + Commercialization Path`
- `Metrics Cluster + Support Modules`
- `Summary Cards + Recommendations Grid`

## Page-Level Judgment Language

Prefer pages that end in one of these judgment modes:

- trend judgment
- capability judgment
- differentiation judgment
- maturity judgment
- landing judgment

Even evidence-heavy pages should still end in a page-level observation, not only a fact pile.

## Weak Expressions To Avoid

Do not reduce the deck to:

- only descriptive definitions with no technical judgment
- only architecture drawings with no explanation of why they matter
- broad application labels with no scenario or value translation
- comparison tables with no verdict area
