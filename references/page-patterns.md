# Page Patterns

Use these approved page patterns to avoid weak generic layouts.

If the user provides a sample deck, inherit the closest pattern from that deck first.

## 1. Chapter Directory Page

Use for:
- every chapter transition

Approved variants:
- Deep blue sidebar directory
- Light geometric directory
- Soft pill / progress directory

Required:
- full chapter list
- current chapter highlighted strongly
- non-current chapters visually weakened

Do not:
- show only a plain bullet list
- use a directory page with no strong left-side device or no current-chapter emphasis

## 2. Research Evidence Mosaic

Use for:
- news / progress / impact pages
- pages with multiple screenshots, facts, quotes, or evidence fragments

Structure:
- strong conclusion title
- 3-6 evidence blocks
- each block should have a clear local title
- page-level narrative should move from claim to evidence to takeaway

Best when:
- the source contains screenshots, events, policy actions, media reactions, or multiple proof points

Do not:
- compress rich evidence into 2 giant paragraphs
- replace an evidence mosaic with only a few empty cards

## 3. Observation Bar + Case Grid + Judgment Strip

Use for:
- application / landing / industry case pages
- vertical industry adoption pages

Structure:
- title + lead sentence
- observation / verdict / watchpoint bar near the top
- 4-6 case cards or grouped case modules in the middle
- bottom judgment strip or page conclusion

Best when:
- the source describes several landing cases across industries

Required:
- the middle area must show case granularity, not just 2-4 broad categories
- the page should end with a page-level judgment

Do not:
- use only four equally weighted white boxes without an observation bar or final judgment

## 4. Comparison Table + Verdict Sidebars

Use for:
- competitive analysis
- vendor / model / strategy comparison

Structure:
- table or matrix on one side
- 1-2 verdict / implication boxes on the other side
- strongest column or row should be visually emphasized

Do not:
- create a giant undifferentiated table without any takeaway area

## 5. Architecture Evolution Row + Explanation Blocks

Use for:
- architecture evolution
- model evolution
- path from one technical paradigm to another

Structure:
- top evolution row, flow row, or central structure
- 2-4 explanation modules below or around it
- one highlighted performance / efficiency takeaway

Best when:
- the source describes dense -> MoE, old -> new, or mechanism upgrades

Do not:
- turn architecture pages into pure bullet lists

## 6. Metrics Cluster + Support Modules

Use for:
- overview / key figures / summary pages

Structure:
- 2-4 highlighted numbers
- supporting cards or bullets around them
- page-level conclusion

Do not:
- use numbers with no surrounding narrative

## 7. Summary Cards + Recommendations Grid

Use for:
- final summary and recommendations

Structure:
- 2-3 summary cards across the top
- 3-4 recommendation modules below
- clear distinction between "what happened" and "what to do"

Do not:
- collapse summary and recommendation into one undifferentiated bullet list

## Disallowed Weak Layouts

These are not allowed unless the source is genuinely too thin:

- large title + several identical empty white boxes
- application pages with only broad category grouping and no case-level structure
- chapter pages that are just plain text lists
- pages with no page-level verdict, observation, or narrative device
- sparse slides with oversized typography when the source clearly supports denser information packaging
