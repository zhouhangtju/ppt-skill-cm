# 报告类型：`project_progress`

本文件定义项目进展类演示文稿的默认章节框架、提取重点、推荐页面范式映射与页级判断语法。

它不重复视觉基线，也不重复标准执行步骤。

## 适用场景

- 阶段进展汇报
- 周报 / 月报 / 季报
- 里程碑复盘
- 重点专项推进情况汇报
- 问题与风险协调会材料

## 默认章节框架

除非用户提供了更强的大纲，否则使用以下框架：

1. 项目目标与总体判断
2. 立项与资源到位进展
3. 项目整体进展与里程碑达成情况
4. 重点工作 / 专题进展
5. 阶段成效与运行效果
6. 问题风险与影响评估
7. 应对举措与需协调事项
8. 下阶段工作计划

## 各章必须回答什么

### 1. 项目目标与总体判断

- 项目原始目标是什么
- 当前总体状态如何
- 本期最重要的判断是什么

### 2. 立项与资源到位进展

- 人、财、物、系统、机制等资源到位到什么程度
- 哪些基础条件已经具备
- 哪些仍在补齐

### 3. 项目整体进展与里程碑达成情况

- 项目整体推进到了哪一步
- 关键里程碑是否按期达成
- 偏差在哪里

### 4. 重点工作 / 专题进展

- 各条主线分别做到了什么
- 哪条主线领先，哪条主线滞后
- 背后原因是什么

### 5. 阶段成效与运行效果

- 当前已产生了哪些结果
- 这些结果如何被量化或感知
- 有哪些可确认的正向信号

### 6. 问题风险与影响评估

- 当前主要问题是什么
- 风险对目标、时间、资源造成什么影响
- 哪些问题需要升级协调

### 7. 应对举措与需协调事项

- 已采取哪些动作
- 下一步准备采取什么动作
- 哪些事项需要上级或横向协调

### 8. 下阶段工作计划

- 下一阶段重点做什么
- 节点如何安排
- 责任如何归属

## 提取重点

优先提取：

- 当前总体状态
- 里程碑进度
- 资源到位情况
- 关键工作流进展
- 阶段成果
- 问题与风险
- 行动举措
- 协调事项
- 下一步计划

## 推荐页面范式

对于总体状态：

- 指标簇 + 支撑模块
- 总判断页

对于资源到位：

- 资源清单表
- 状态卡片页

对于整体进展与里程碑：

- 时间线 + 状态条
- 里程碑进度页

对于重点工作流：

- 多卡片矩阵
- 分专题推进页

对于阶段结果：

- 指标页 + 成果模块

对于问题与风险：

- 风险矩阵 + 行动侧栏
- 对比表 + 影响判断

对于应对举措与协调事项：

- 行动清单 + 协调清单

对于下阶段计划：

- 路线图页
- 阶段计划页

## 页级判断语言

进展类页面应优先强调：

- 现在处于什么状态
- 达成了什么 / 没达成什么
- 偏差与风险在哪里
- 需要采取什么动作

## 需要避免的弱表达

不要把整份演示文稿降成：

- 机械流水账
- 只有完成项，没有问题判断
- 只有问题，没有应对动作
- 只有计划，没有状态基线
